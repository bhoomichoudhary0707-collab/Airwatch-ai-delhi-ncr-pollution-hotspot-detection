## The Problem

Delhi-NCR's air quality crisis is well documented — but three gaps remain unsolved by existing tools:

1. **Citizens** feel the pollution but have no way to prove where it's coming from.
2. **Officials** receive raw AQI numbers but no attributed cause.
3. **Nobody** tracks whether a flagged pollution hotspot is ever actually resolved.

Most existing solutions stop at *detection* — showing AQI on a map. AirWatch AI goes further.

## The Idea

A single continuous workflow, from raw sensor data to a resolved complaint:

```
DETECT → PREDICT → ATTRIBUTE → REPORT → TRACK RESOLUTION
```

| Stage | What it does |
|---|---|
| **Detect** | Identify pollution hotspots from sensor and satellite data |
| **Predict** | Forecast how a hotspot will evolve over the next 6–48 hours |
| **Attribute** | Explain the *probable* cause of a hotspot, with supporting evidence |
| **Report** | Generate a structured, submission-ready complaint dossier |
| **Track** | Follow the incident through a 7-stage accountability lifecycle to resolution |

## Features

### 🖥️ Command Center
Live NCR-wide AQI, PM2.5, PM10, active hotspot count, and a one-click **Simulate Demo Incident** panel (Industrial Emission Spike, Agricultural Burning Ingress, Freight Traffic Gridlock) for live demonstration.

### 🗺️ Pollution Map
Interactive Delhi-NCR map with monitoring stations, hotspot markers, wind dispersion vectors, industrial/source zone overlays, and citizen report pins.

### 📊 Hotspots
Searchable, sortable, filterable table of every detected hotspot with pollutant levels (PM2.5, PM10, NO2, SO2), severity, probable source, and confidence score.

### 🧭 AI-Assisted Source Attribution
For every hotspot, an explainable panel shows a **probable source** (e.g. industrial emissions, traffic gridlock, agricultural burning) with a **confidence score** and the supporting evidence (wind direction, proximity to source zones, pollutant signature, seasonal pattern) — always framed as a probability, never a confirmed cause.

### 📈 Forecast
6h / 12h / 24h / 48h pollution forecasts per monitoring station, clearly distinguishing observed vs. model-predicted data.

### 📢 Citizen Reports
A simulated citizen-reporting form (location, category, description, optional photo) that feeds directly into the hotspot and map system.

### 📋 Complaints & Actions
Auto-generated, structured environmental complaint dossiers tied to each hotspot, moved through a 7-stage lifecycle:

```
Detected → Flagged → Report Generated → Prepared for Submission
→ Investigating → Action Taken → Resolved
```

### ✅ Accountability
A dashboard tracking every incident's full lifecycle, open/resolved counts, and average resolution time — the piece most pollution-monitoring tools never build.

### 🤖 AI Assistant
A grounded assistant that answers questions ("Why is Ghaziabad flagged?", "What complaints are unresolved?") using only the app's own live data — never invented information.

### 📚 Data & Methodology
Full transparency page separating **current prototype** methods from **planned production integrations**.

## ⚠️ Prototype Disclaimer

AirWatch AI is a **hackathon prototype**. It is **not** connected to live government systems, and no complaint generated by this tool has been submitted to any real authority. All simulated data is clearly labeled in-app as:

- `PROTOTYPE DATA`
- `MODEL PREDICTION`
- `AI-ASSISTED PROBABLE SOURCE`
- `SIMULATED CITIZEN REPORT`
- `PROTOTYPE COMPLAINT`

Source attribution is always expressed as a **probable cause with a confidence score** — never as a confirmed fact — and complaints are labeled **"prepared for submission,"** never "submitted."

## Why This Matters

- **Pilotable** — built for the exact kind of constituency pilot this hackathon is designed to fund.
- **Honest by design** — every AI claim is a probability with evidence, built for real government trust rather than hype.
- **Closes the loop** — the only stage most pollution tools skip: tracking a hotspot all the way to resolution.
